# denoise 不該隨 fidelity 變動 —— 那會抵銷掉 ControlNet 的用處

## 背景

面板只給使用者一個「fidelity」滑桿（spec 2.1），內部要映射到生成參數。
第一版只映射到 ControlNet 權重，實測產出「看起來像 SketchUp 截圖加了點材質」，
不像算圖結果。

## 第一次修正（錯的）

我讓 denoise 隨 fidelity **反向**變動：低保真 = 高 denoise（更自由）、
高保真 = 低 denoise（更貼原圖）。看起來很合理。

實測三組：

| denoise | edge 權重 | 結構 | 外觀 |
|---|---|---|---|
| 0.65 | 0.74 | ✅ 完整 | ❌ 像截圖 |
| 0.79 | 0.48 | ❌ **量體整個跑掉** | ✅ 像照片 |

兩端都不堪用，而「照片般但結構正確」的中間區域**反而到不了**。

## 根本錯誤

我把兩個**獨立的軸**綁在一起了。

- `denoise` 決定**模型能重畫多少**（材質、光影、質感）
- ControlNet 權重決定**幾何要多貼合**

**ControlNet 的整個意義就是讓這兩件事可以同時成立**：
denoise 開高讓模型自由重畫外觀，同時由控制圖把幾何按住。
讓它們同進同退，等於把 ControlNet 的好處抵銷掉 ——
高 denoise 時控制圖太弱擋不住漂移，低 denoise 時模型根本沒在畫。

## 決定

```ruby
DENOISE = 0.75          # 固定。給外觀自由。
weights_for(f) = { edge: 0.55 + 0.45f, depth: 0.30 + 0.35f }   # 按住幾何
```

驗證（denoise 0.75 / edge 0.82）：結構完整**且**材質光影被重畫，58.9 秒。

## edge 權重的下限為什麼是 0.55 而不是 0

實測 0.48 時建築量體就整個跑掉了 —— 12 個窗變成完全不同的形狀。

低於這個值，產出就不再是「這棟建築的算圖」，
而是「用這張圖當靈感重新生成」。**那不是渲染外掛該提供的東西** ——
使用者要的是他畫的那棟建築，不是一棟看起來很美的別的建築。

滑桿最左端仍應該可用，所以下限訂在「還認得出是同一棟建築」的位置。

## 被否決的選項

- **讓 denoise 也可調（第二個滑桿）**：違反 spec 2.1 的「單一旋鈕」。
  而且實測顯示使用者其實不需要調它 —— 0.75 在整個 fidelity 範圍都合適。
- **下限開到 0**：見上，那個區間的產出對渲染用途沒有意義。

## 未解

SD1.5 在 640² 的品質天花板。產出是「算圖」而不是「截圖」了，
但離 photoreal 還有距離。換 SDXL 或更高解析度會改善，
代價是記憶體（實測 768 就因換頁而慢 7 倍）。
這是本機生成的固有限制，不是映射的問題。
