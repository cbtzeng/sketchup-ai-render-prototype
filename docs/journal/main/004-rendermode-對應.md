# RenderMode 只有 4 個有效值，edge pass 用 5（單色）而非 1（隱藏線）

## 背景

第一輪探查（journal 002 同批）在只有一面無貼圖白牆的模型上跑，
RenderMode 2/3/4/7 產出的 PNG 位元組完全相同，無法區分 shaded 與 textured。
可行性清單 2.4 標為 🟡 部分確定。

## 實測

`tools/spike/probe_rendermode.rb` 自建場景：貼圖面（Asphalt_01_1K）+ 純色面（紅）
+ 預設面（白）+ 立體量體 + 開啟陰影。

| mode | md5 相同組 | 實際外觀 |
|---|---|---|
| 0 | 獨立 | 線框，面不繪製 |
| 1 | 獨立 | 隱藏線：**面填背景色**（灰 192），黑邊線，無面著色 |
| 2 / 3 / 4 / 7 | **同一組** | 著色含貼圖：Asphalt 正常顯示為深褐、紅面為紅、白面為白 |
| 5 | 獨立 | 單色：**面恆為純白**，黑邊線，無面著色 |
| 6 | 獨立 | 與 2 相同但整體壓暗約 7%（255→238、129→103） |

**即使在有貼圖的場景上，2/3/4/7 仍然位元組完全相同。**
貼圖有正常渲染，所以貼圖顯示是由獨立的 `Texture` 布林 key 控制，不歸 RenderMode 管。

## 決定

`RENDER_MODE_FOR_EDGE_PASS = 5`（單色），**不是 1（隱藏線）**。

## 理由

我原本在 options_keys.rb 寫的是「1 = 隱藏線 ← edge pass 用這個」。看了實際畫面才發現不對：

- **mode 1 的面採背景色**。面和背景是同一個灰，物件輪廓只靠那條黑邊線撐著。
  若之後有人改了 `BackgroundColor`，面的顏色會跟著變 —— 多一個隱性相依。
- **mode 5 的面恆為純白**，與 `BackgroundColor` 完全無關。
  配上白背景就是乾淨的「白底黑線」，正是 edge control 要的東西。

兩者在「把背景設成白色」時結果會收斂，但 5 少一個相依，行為更可預測。

## 被否決的選項為什麼不行

- **mode 1 + 強制白背景**：可行但脆弱。多一個必須同時成立的條件，
  而且如果哪天忘了設背景，產出的是「灰底黑線」，ControlNet 吃到的對比度就變了 ——
  這種錯誤不會報錯，只會讓結果悄悄變差。
- **mode 0（線框）**：面不繪製，看得到背面所有邊線，不是遮擋正確的線稿。
- **mode 6**：與 2 相同但壓暗，沒有任何好處。

## 未解

mode 6 的實際用途未確認（推測與透視/X-ray 有關，但沒驗證）。
本專案不使用，不影響 MVP。3/4/7 為何存在也未確認 —— 可能是歷史值或 clamp 行為。
